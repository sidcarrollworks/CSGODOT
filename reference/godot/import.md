# Godot 4.7: importing assets

Source: godot-docs branch 4.7 @9adca4c (2026-09-21). Read when: running or changing the import step (`scripts/common.sh`, `scripts/write_import_settings.gd`, `scripts/prepare_export.gd`), adding a file type under `res://`, hand-editing a `.tscn`, `.tres` or `.import` file, loading glTF at runtime (`MapImporter`), or changing texture, model or sound import settings.

This page is about what Godot does. What CS2's export looks like, and what was measured on dust2, is in `reference/asset-pipeline.md`; read that too and do not repeat it here. Costs are in `reference/performance.md`.

## Rules for this project

- Load imported assets with `load()`/`ResourceLoader`, never `FileAccess`: the imported data lives in `res://.godot/imported/`, and `FileAccess` on the source file "will work in the editor, but it will break in the exported project" (`tutorials/assets_pipeline/import_process.rst`). `FileAccess` is right only for files Godot does not import (the `.gltf` JSON the scripts parse, `.json`, `.txt`, CSVs with `importer="keep"`).
- Run `--import` with an editor build before any `--script` run. It is marked editor-only, "Starts the editor, waits for any resources to be imported, and then quits. Implies `--editor` and `--quit`" (`tutorials/editor/command_line_tutorial.rst`). An export template binary cannot import.
- Write a texture's `.import` settings before its first import (as `write_import_settings.gd` does). Headless, nothing is ever "detected" as 3D or as a normal map, so the defaults stay: Lossless, no mipmaps (`classes/class_resourceimportertexture.rst`: `compress/mode` = 0, `mipmaps/generate` = false).
- Commit `.import` files for every imported file that is itself committed (the docs: "Make sure to commit these files"). Never commit `.godot/` (it is regenerated; the repo ignores it). `assets/` is gitignored, and its `.import` files go with it: they are regenerated by `write_import_settings.gd`, so a setting that matters must live in that script, not in a hand-edited `.import` under `assets/`.
- A new `.csv` under `res://` needs a committed `.csv.import` with `importer="keep"` next to it (as `reference/**/*.csv.import` already have). Godot's CSV importer is the translation importer (`tutorials/assets_pipeline/importing_translations.rst`); without the `keep` file the CSV is imported as a translation and `.translation` output appears (gitignored here). (Inferred from the docs plus the repo's existing keep files.)
- Put `.gdignore` (empty; it takes no patterns) in any folder under `res://` Godot must not import, as `assets/**/lightmaps/probes/` does. Files there cannot be `load()`ed any more, only read with `FileAccess` (`tutorials/best_practices/project_organization.rst`).
- Hand-written `.tscn`/`.tres` files: omit properties that equal their defaults (the editor drops them on save anyway), list `sub_resource`s before anything that refers to them, and give every scene exactly one root node without `parent=` (`engine_details/file_formats/tscn.rst`).
- Never reach for `EditorScenePostImport` for game logic: import scripts are `@tool` editor code that only runs during import. What the runtime path (`GLTFDocument`) sees, the import script never touched.
- Keep both glTF load paths in mind: `MapImporter._load_scene` uses the imported `PackedScene` when there is one and otherwise parses the `.gltf` with `GLTFDocument`. The two do not produce the same scene (see "Runtime glTF"), so a check that passes on one path proves little about the other.

## How the import pipeline works

`tutorials/assets_pipeline/import_process.rst`, `tutorials/best_practices/project_organization.rst`

- Any file in the project folder that Godot can import is imported automatically. The result goes to the hidden `res://.godot/imported/` folder, named `<file>-<md5 of path>.<ext>` with a `.md5` beside it (the doc's example: `example.png-218a8f2b3041327d8a5756f3a245f83b.ctex` and `.md5`).
- Next to each source file Godot writes `<file>.import`, which holds the import settings and the uid.
- Reimport happens when the MD5 of the source asset changes, with that asset's own settings. For a text `.gltf` that is the `.gltf` file, not its `.bin` or textures: `src/map/export_offset_fix.gd` appends a newline to the `.gltf` after editing the `.bin` for exactly this reason. The repo also relies on a changed `.import` `[params]` triggering a reimport (`write_import_settings.gd` header).
- If anything in `.godot/imported/` is deleted, the asset is imported again (`editor/import/reimport_missing_imported_files` = true, `classes/class_projectsettings.rst`). Deleting `.godot/` forces a full reimport: about a minute for dust2, and about four minutes the first time for the 8192² lightmap `.exr` (asset-pipeline.md).
- `editor/import/use_multiple_threads` = true: import runs on several threads.
- Native formats (`.tscn`, `.scn`, `.tres`, `.res`) are not imported and have no import options. An `.escn` is the TSCN format but is imported (compiled to binary `.scn` in `.godot/imported/`) (`engine_details/file_formats/tscn.rst`).
- Import type can be changed per file. "Keep File (exported as is)" skips import but keeps the file in exports (the CSVs here); "Skip File (not exported)" skips both.
- Project-wide import defaults live in Project Settings > Import Defaults (editor GUI; they land in `project.godot`). The project sets none; per-file `.import` files carry everything.
- `.gdignore`: an empty file named `.gdignore` in a folder stops Godot importing anything in it, hides it from the FileSystem dock and leaves it out of exports. Its contents are ignored: no patterns. Resources there can no longer be `load()`ed or `preload()`ed.
- Case: the exported PCK filesystem is case-sensitive, where Windows (Sid's machine) is not. A path that works in the editor on Windows can fail when exported, or on Linux CI. CS2 names differ in case in places (`leg_upper_l` in the model description, `leg_upper_L` in the glTF: asset-pipeline.md), so compare names in code, not paths, case-insensitively.

## Running the import headless

`tutorials/editor/command_line_tutorial.rst`, `classes/class_audioserver.rst`, `classes/class_projectsettings.rst`

- `godot --headless --path <project> --import`: `--headless` is `--display-driver headless --audio-driver Dummy`. `--import` implies `--editor` and `--quit`, so it needs an editor build and a valid `project.godot`. `--export-release/--export-debug/--export-pack` imply `--import`.
- The first `--import` on a fresh checkout also builds the global class list; `scripts/run_tests.sh` relies on it ("Without it the test script cannot see MovementSolver and friends, and fails to parse"). So a CI or cloud run must import even when `assets/` is absent (`run_tests.sh` does).
- What must exist before the import: the texture `.import` files (`write_import_settings.gd`) and the export fixes on the `.bin` (`prepare_export.gd`); `scripts/common.sh import_assets` runs both with `--script` first, then `--import`, and logs to `.godot/import.log`.
- The GPU texture compressor (`rendering/textures/vram_compression/compress_with_gpu` = true) only works "on a device which supports either Vulkan, Direct3D 12, or Metal as a rendering driver", and only for BC1, BC3, BC4, BC5 and BC6. A `--headless` import has no rendering device, so it compresses on the CPU (inferred). That is the likely reason the lightmap's BC6H import takes minutes: an import run with a window on Sid's machine may be much faster (not measured).
- `rendering/textures/vram_compression/import_s3tc_bptc` and `import_etc2_astc` default to false and are overrides: "The texture importer will always import the format the host platform needs." On Windows and Linux desktop that is S3TC/BPTC.
- The import never runs during a game tick. What `load()` reads at runtime is the already-imported file; loading it still reads the disk, so do it before the round (as `SoundBank.load_sets` and `WeaponSounds._load_all` do), never in `GameWorld`'s tick.

## The `.import` file

`tutorials/assets_pipeline/import_process.rst`; the key names are the importer's option names in `classes/class_resourceimporter*.rst`.

It is an INI-style `ConfigFile`. The sections the repo reads and writes:

```
[remap]
importer="texture"                 ; the importer's name ("keep" for keep-as-is)
type="CompressedTexture2D"         ; the resource type it produces
uid="uid://..."                    ; filled in by Godot on first import
path="res://.godot/imported/..."   ; where the imported file is (written by Godot)

[deps]
source_file="res://assets/.../foo.png"
dest_files=[...]                   ; written by Godot

[params]
compress/mode=2
mipmaps/generate=true
...
```

- `[params]` keys are exactly the `ResourceImporter*` property names (`compress/mode`, `mipmaps/generate`, `nodes/root_scale`, `force/mono`...). Enum options are stored as integers.
- Minimum that works before the first import: `[remap] importer` and `type`, `[deps] source_file`, and the `[params]` you care about. Godot fills in the rest, uid included (`write_import_settings.gd`, which has been run against real content).
- Keep the uid when rewriting a file: load it with `ConfigFile`, change `[params]`, save. A new uid breaks every `uid://` reference to that asset (inferred from `tscn.rst`'s description of uids).
- A keep file is just `[remap] importer="keep"` plus `[deps] source_file` (the repo's CSVs; Godot adds a uid).

## Text scenes and resources (`.tscn`, `.tres`)

`engine_details/file_formats/tscn.rst`

File layout, in this order: file descriptor, `ext_resource`s, `sub_resource`s, nodes, connections. Each entry is a heading `[<kind> key=value ...]` followed by `key = value` lines. Comments start with `;` and are dropped when the editor saves. Whitespace does not matter outside strings.

- **Descriptor.** Scene: `[gd_scene format=3 uid="uid://cecaux1sm7mo0"]`. Resource: `[gd_resource type="ArrayMesh" format=3 uid="uid://..."]`, with the resource's own properties under a `[resource]` heading at the end. `format=3` is Godot 4 (`format=2` is Godot 3). `load_steps=<n>` is written by pre-4.6 saves and is "deprecated and should be ignored if present": the repo's hand-written scenes still carry it, which is harmless.
- **uid.** A string id so the engine can track a file that moves "even while the editor is closed"; scripts can `load("uid://...")`. It is stored in the file itself (for imported files, in the `.import`; for scripts and shaders, in a `<file>.uid` sidecar, which the repo commits: 160 of them). There is no central uid database in the project. `ResourceUID.uid_to_path()`, `path_to_uid()` and `ensure_path()` convert (`classes/class_resourceuid.rst`). A descriptor may omit `uid`; the editor adds one on save (inferred; the repo's hand-written `.tscn`s have none and load).
- **ext_resource.** `[ext_resource type="Texture2D" uid="uid://ccbm14ebjmpy1" path="res://gradient.tres" id="2_eorut"]`. `path` may be `res://` absolute or relative to the `.tscn`. `uid` is optional (`src/player/player.tscn` has none). Referenced in values as `ExtResource("2_eorut")`.
- **sub_resource.** `[sub_resource type="CapsuleShape3D" id="CapsuleShape3D_fdxgg"]` then its properties. Referenced as `SubResource("CapsuleShape3D_fdxgg")`. Sub-resources have no uid. A sub-resource must appear before anything that references it. `ext_resource` and `sub_resource` ids are separate namespaces, so the same id may appear in both. The editor's ids look like `Type_xxxxx` and `N_xxxxx`, but any unique string works.
- **node.** `[node name="Arm" type="Node3D" parent="." unique_id=1010797352]`.
  - The root has no `parent`. There must be exactly one root, or "Godot will fail to import the file".
  - `parent` is the path from the root, without the root's name: `"."` for the root's children, `"Arm/Hand"` deeper.
  - `unique_id` (an integer) tracks a node through renames and moves. It is only written by 4.6 or later and "not guaranteed to be present", so a hand-written node may leave it out. Do not copy one node's `unique_id` onto another (inferred: it must stay unique within the scene).
  - Other heading keys: `instance=ExtResource("id")` (an instanced scene; then there is no `type`), `instance_placeholder`, `owner`, `index` (order among siblings; inherited nodes come first when absent), `groups=[...]`, and `node_paths=PackedStringArray("follow_node")`, which lists properties that are exported as a `Node` type but stored as `NodePath`.
- **Values.** Godot's Variant text syntax: `Transform3D(1, 0, 0, 0, 1, 0, 0, 0, 1, x, y, z)` (basis columns x, y, z, then origin), `Vector3(...)`, `Quaternion(x, y, z, w)`, `Color(r, g, b, a)`, `NodePath("..")`, `PackedFloat32Array(...)`, `&"string_name"`, and dictionaries and arrays in JSON-like form. `NodePath("Mesh:scale.x")` points at a property component.
- **Skeleton3D** node properties: `bones/<id>/position = Vector3`, `bones/<id>/rotation = Quaternion`, `bones/<id>/scale = Vector3`, each optional. These are poses; rests come from the imported skeleton.
- **BoneAttachment3D**: `bone_name = "hand.R"` and `bone_idx = 55`, as properties.
- **AnimationPlayer**: `libraries = { "": SubResource("AnimationLibrary_x") }`. The empty-named library is the default: its clips play as `"name"`. A named library's clips play as `"library/name"`. The `Animation` format is in `animation.md` on this site.
- **ArrayMesh** in a `.tres`: `_surfaces = [{ "aabb", "attribute_data", "bone_aabbs", "format", "index_count", "index_data", "lods", "material", "name", "primitive" (3 = triangles), "skin_data", "vertex_count", "vertex_data" }]`, mostly `PackedByteArray`. Do not hand-write meshes. For saved meshes the import docs say use `.res`: "`.tres` is inefficient for writing large amounts of data" (`advanced_import_settings.rst`).
- **Connections**: `[connection signal="..." from="path" to="path" method="..."]` (the section exists; the doc gives no example).

## 3D scenes: the editor import

`tutorials/assets_pipeline/importing_3d_scenes/*.rst`, `classes/class_resourceimporterscene.rst`

The pipeline: glTF → `GLTFState` (in memory) → Godot scene → `ResourceImporterScene` applies the import settings → saved as a scene in `.godot/imported/`. `load("res://...x.gltf")` returns that `PackedScene`. `ResourceImporterScene` is not used for `.tscn`/`.scn`.

The options (`[params]` names and defaults) that bear on CS2 exports:

| Option | Default | Why it matters here |
|---|---|---|
| `nodes/root_scale` | 1.0 | The exports are in metres, and the runtime scales the root by 39.37. Setting 39.37 with `nodes/apply_root_scale` = true (the default) would bake the scale into "the descendant nodes, meshes, animations, bones", which would leave physics shapes and bones unscaled. It is an option only: every metres-to-units conversion in the code (`MapImporter.SOURCE2_VIEWER_SCALE`, `SkinnedHitboxes`, `Ragdoll`) would have to change with it, and the runtime `GLTFDocument` path would not get it. |
| `nodes/use_name_suffixes` / `nodes/use_node_type_suffixes` | true / true | Name suffixes change types: `-col`, `-convcol`, `-colonly`, `-convcolonly`, `-occ`, `-occonly`, `-navmesh`, `-rigid`, `-vehicle`, `-wheel`, `-noimp` on nodes, `-alpha` and `-vcol` on materials. They match with `-`, `$` or `_`, case-insensitive, so `_col` or `_rigid` at the end of a Valve node name would turn it into collision or a RigidBody3D. Clips whose names start or end with `loop` or `cycle` (no separator needed) import looping. Set both to false for editor import that matches the runtime import. With `use_node_type_suffixes` false, `-noimp`, `-vcol` and `-loop` are still honoured; with `use_name_suffixes` false, the glTF importer itself still checks `-loop`. |
| `meshes/generate_lods` | true | Import-time LOD for every mesh; costs import time and file size. See `tutorials/3d/mesh_lod.rst`. Its weld ignores CUSTOM0 to 3, so it crosses seams only a custom channel marks (`rendering.md`, "Automatic mesh LOD"). |
| `meshes/create_shadow_meshes` | true | Welded shadow meshes. |
| `meshes/ensure_tangents` | true | Mikktspace tangents where the file has none. |
| `meshes/light_baking` | 1 | GI mode for `LightmapGI`/`VoxelGI`; 2 ("Static Lightmaps") also unwraps UV2 at import, which would replace nothing here (CS2's lightmap UVs come in `TEXCOORD_1`) but costs time. Enum order inferred: 0 disabled, 1 static, 2 static lightmaps, 3 dynamic. |
| `meshes/force_disable_compression` | false | Mesh compression; the docs advise disabling it for meshes "larger than a few thousand meters". dust2 is about 127 m across in the export's metres. |
| `skins/use_named_skins` | true | Skin binds by bone name, not index. The runtime `GLTFState.use_named_skin_binds` defaults to false. |
| `animation/import` | true | |
| `animation/fps` | 30 | Curves are baked to linear keys at this rate. CS2 clips are sampled (inferred); raise it if 30 Hz keys visibly smooth out a fast clip. |
| `animation/remove_immutable_tracks` | true | Drops tracks that "only contain default values". This is the likely cause of the dropped constant scale tracks reported in asset-pipeline.md (first-person body row). |
| `animation/trimming` | false | |
| `animation/import_rest_as_RESET` | false | Adds a `RESET` clip holding the bone rests. That is the blend's reference for missing tracks and relevant to `deterministic` blending (see animation.md). |
| `import_script/path` | "" | An `EditorScenePostImport` script. |
| `materials/extract` | 0 | 0 keep internal, 1 extract once, 2 extract and overwrite, into `materials/extract_path` as `.tres` (0), `.res` (1) or `.material` (2). |
| `_subresources` | {} | Per-node, per-mesh, per-material and per-animation options from the Advanced dialog (skip import, generate physics, save to file, animation slices, `bone_map`). Hand-editing is possible but undocumented. |

Other facts:
- Import as **Animation Library** instead of Scene (Import dock's import mode) makes a `.gltf` produce an `AnimationLibrary`, for "one set of animations for several characters". Meshes and materials are discarded (`GLTFDocument.IMPORT_FLAG_DISCARD_MESHES_AND_MATERIALS` "is always enabled"). The docs say the editor must restart after changing the mode. That would fit the per-clip glTFs under `animation/anims/` if their rig nodes were not also used (they are: the first-person clips carry both rigs, asset-pipeline.md).
- **Animation filter script** (per-scene option): lines `@+*_Loop, +Arm_Left*, -*Attack` select animations; the following `+pattern`/`-pattern` lines keep or drop tracks, in order, later lines overriding earlier. If an animation is selected and no track lines follow, all its tracks are dropped. Matching is `String.matchn` (case-insensitive, `*` and `?`).
- **Advanced settings per animation**: an optimizer (on by default), "Save to File" (keeps custom tracks across reimport), and slices (only when the file has a single animation named `default`).
- **Scene inheritance**: an inherited scene of an imported one cannot remove base nodes or edit sub-resources. Everything else is allowed.
- **Coordinate conventions** (`model_export_considerations.rst`): Godot is right-handed and Y-up with -Z forward for cameras. An asset's front faces +Z (glTF convention), so a character model faces the camera by default. Use `look_at(..., use_model_front = true)` and `Vector3.MODEL_*` for model-space directions. The CS2 export already turns Source (x, y, z) into glTF (y, z, x) (asset-pipeline.md).
- **Occluders at import**: per-node "Generate > Occluder" (Mesh + Occluder or Occluder Only) and the `-occ`/`-occonly` suffixes make `OccluderInstance3D`s. That is relevant to the occlusion-culling work; see `tutorials/3d/occlusion_culling.rst`.

## Runtime glTF: `GLTFDocument` + `GLTFState`

`tutorials/io/runtime_file_loading_and_saving.rst`, `classes/class_gltfdocument.rst`, `classes/class_gltfstate.rst`, `importing_3d_scenes/node_type_customization.rst`

```gdscript
var document := GLTFDocument.new()
var state := GLTFState.new()
var err := document.append_from_file(absolute_path, state)   # flags = 0, base_path = ""
if err == OK:
    var root := document.generate_scene(state)  # bake_fps = 30, trimming = false, remove_immutable_tracks = true
```

- This path does **not** run `ResourceImporterScene`: no name suffixes, no LOD generation, no shadow meshes, no import script, no per-node options, no texture import settings. The docs present turning suffixes off as the way to make editor import "more similar to importing files at runtime", and recommend `GLTFDocumentExtension` "for an import workflow that works at runtime".
- Textures referenced by a `.gltf` are loaded from `base_path`, which `append_from_file` sets to the file's folder. For `append_from_buffer`, set `state.base_path` first.
- Defaults that differ from the editor import: `GLTFState.use_named_skin_binds` = false (editor `skins/use_named_skins` = true); `IMPORT_FLAG_GENERATE_TANGENT_ARRAYS` (8) is off unless passed in `flags` (editor `ensure_tangents` = true, inferred to map to it); `IMPORT_FLAG_USE_NAMED_SKIN_BINDS` = 16, `IMPORT_FLAG_DISCARD_MESHES_AND_MATERIALS` = 32, `IMPORT_FLAG_FORCE_DISABLE_MESH_COMPRESSION` = 64.
- `GLTFState.handle_binary_image_mode` = 1 (`HANDLE_BINARY_IMAGE_MODE_EXTRACT_TEXTURES`); `bake_fps` = 30; `create_animations` = true; `import_as_skeleton_bones` = false.
- **New in 4.7:** `GLTFDocument.texture_map_mode` = `TEXTURE_MAP_MODE_REMAP_TO_STANDARD_MATERIAL` (1) remaps glTF texture maps into `StandardMaterial3D` slots. `TEXTURE_MAP_MODE_DO_NOT_REMAP` (0) is "the behavior in Godot 4.6 and earlier". Code that reads textures off the generated materials (for example to build the lightmapped or blended shaders) should be checked against 4.7's default (not verified here).
- `generate_scene` returns an un-owned node tree built on the calling thread. On dust2 it parses 3613 meshes, so it is a load-time cost only, never inside a tick.
- Extending: `GLTFDocument.register_gltf_document_extension(ext, first_priority = false)` (static). Extensions must be stateless; keep data in `GLTFState.set_additional_data()`/`get_additional_data()`. This is how glTF `extras` (the vmat paths and shader flags on every material) could be read at import rather than by re-parsing the JSON.
- `FBXDocument`/`FBXState` are drop-in equivalents for `.fbx` (not used).

## Textures

`tutorials/assets_pipeline/importing_images.rst`, `classes/class_resourceimportertexture.rst`

- Formats: PNG (8 bits per channel, no HDR), EXR and HDR (HDR), JPEG, TGA, WebP, BMP, DDS (its mipmaps are used as they are), KTX (2D only), SVG (rasterised at import).
- Import types include Texture2D (default, `CompressedTexture2D`), Image, Texture2DArray, Texture3D, Cubemap (order X+, X-, Y+, Y-, Z+, Z-), CubemapArray, and others.
- `compress/mode`: 0 Lossless (default), 1 Lossy, 2 VRAM Compressed, 3 VRAM Uncompressed, 4 Basis Universal. VRAM Compressed cuts video memory by about 4 to 6 times (a 4096² RGBA8 with mipmaps: 85.33 MiB lossless, 21.33 MiB VRAM compressed).
- `compress/high_quality` = false: false gives S3TC (BC1 opaque, BC3 with alpha; the docs say BC3 "or normal map (RGTC)" too, but the gun imports' normal maps are BC5, `RGTC_RG`, one byte a pixel as BC3 is: measured 2026-09-25, `reference/research/weapon-preload.md`). True gives BPTC: BC7 for SDR, **BC6H for HDR**. "BPTC and ASTC support VRAM compression for HDR textures, but S3TC and ETC2 do not." `write_import_settings.gd` does not set `high_quality`, yet asset-pipeline.md measured the lightmap `.exr` importing as BC6H (90 MB). The docs imply it would get RGBE9995 without `high_quality`, so check the imported format before relying on either (not verified).
- `compress/hdr_compression` = 1 (Opaque Only). 0 converts HDR to RGBE9995 (32 bits per pixel). 2 forces compression and drops alpha.
- `compress/normal_map`: 0 Detect (default), 1 Enable (RGTC), 2 Disabled. RGTC keeps only R and G: a custom shader that reads a normal map's blue channel will read junk. Built-in materials ignore blue. Godot wants OpenGL-style (Y+) normals. For DirectX-style ones use `process/channel_remap/green` = Green Inverted (`process/normal_map_invert_y` is deprecated). asset-pipeline.md checked CS2's normals as green-up.
- `compress/channel_pack` = 0 (sRGB Friendly). 1 Optimized allows RG formats.
- `mipmaps/generate` = false; `mipmaps/limit` is unimplemented.
- `detect_3d/compress_to` = 1 (VRAM Compressed on detection). The project sets 0 so nothing changes behind its back.
- `roughness/mode` and `roughness/src_normal`: roughness filtering from a normal map at import (specular anti-aliasing).
- `process/fix_alpha_border` = true, `process/premult_alpha` = false, `process/hdr_as_srgb` = false, `process/hdr_clamp_exposure` = false (clamps "sparkles" in HDR skies), `process/size_limit` = 0. The size cap is 32768 px on any side (16383 for Lossy, 16384 for Basis).
- `process/channel_remap/{red,green,blue,alpha}`: per-channel source (R, G, B, A, inverted, unused, zero, one). That is a way to pull a mask out of a packed CS2 texture at import without a shader.
- Filtering and repeat are not import options in Godot 4: they belong to the material (`BaseMaterial3D` sampling) or the shader's `sampler2D` hints.

## Audio import (details in audio.md)

`tutorials/assets_pipeline/importing_audio_samples.rst`, `classes/class_resourceimporterwav.rst`, `classes/class_resourceimporteroggvorbis.rst`, `classes/class_resourceimportermp3.rst`

- WAV `[params]`: `compress/mode` = 2 (Quite OK Audio, the default; 0 PCM, 1 IMA ADPCM), `edit/loop_mode` = 0 (detect from the WAV), `edit/loop_begin` = 0, `edit/loop_end` = -1, `edit/normalize` = false, `edit/trim` = false, `force/mono` = false, `force/max_rate` = false, `force/max_rate_hz` = 44100, `force/8_bit` = false.
- Ogg Vorbis and MP3 `[params]`: `loop` = false, `loop_offset` = 0 (seconds), `bpm` = 0, `beat_count` = 0, `bar_beats` = 4.
- CS2's `.vsnd_c` decompile to WAV (and a few MP3). The default QOA is lossy but cheap. To keep the game's samples bit-exact, set `compress/mode` = 0 for them in the same way textures get their settings (a choice, not done).

## Class notes

**ResourceImporterScene** (`classes/class_resourceimporterscene.rst`): the table above. `nodes/root_type` = "" (Node3D), `nodes/root_name` = "" (file name), `nodes/root_script` = null (attaches a script and can change the root type), `nodes/import_as_skeleton_bones` = false (every node becomes a bone of one Skeleton3D), `array_mesh/deduplicate_surfaces` = true, `mesh_library/use_node_names_as_mesh_names` = false.

**ResourceImporterTexture**: see Textures. Produces `CompressedTexture2D` (`.ctex`). `ResourceImporterImage` produces `Image` for CPU-side reading.

**ResourceImporterWAV / ResourceImporterOggVorbis / ResourceImporterMP3**: see Audio import. `AudioStreamWAV.load_from_file(path, options)` takes the same option names as a Dictionary at runtime.

**EditorScenePostImport** (`classes/class_editorscenepostimport.rst`): `@tool`, `extends EditorScenePostImport`, `func _post_import(scene: Node) -> Object`, which **must return** the scene (or a replacement). `get_source_file() -> String`. Set with `import_script/path`. It runs in the editor during `--import`, not at runtime.

**GLTFDocument** (`classes/class_gltfdocument.rst`): `append_from_file(path: String, state: GLTFState, flags: int = 0, base_path: String = "") -> Error`; `append_from_buffer(bytes, base_path, state, flags = 0)`; `append_from_scene(node, state, flags = 0)`; `generate_scene(state, bake_fps = 30, trimming = false, remove_immutable_tracks = true) -> Node`; `generate_buffer(state) -> PackedByteArray`; `write_to_filesystem(state, path) -> Error` (`.glb` or `.gltf` by extension); `root_node_mode` = SINGLE_ROOT; `texture_map_mode` = REMAP_TO_STANDARD_MATERIAL (4.7); `visibility_mode` = INCLUDE_REQUIRED (`KHR_node_visibility`); static `get_supported_gltf_extensions()`.

**GLTFState** (`classes/class_gltfstate.rst`): `base_path`, `bake_fps` = 30.0, `create_animations` = true, `handle_binary_image_mode` = 1, `import_as_skeleton_bones` = false, `use_named_skin_binds` = false, `json` (the parsed JSON, readable after `append_*`), `buffers`, `get_nodes()`, `get_animations()`, `get_scene_node(gltf_node_index)`, `get_animation_player(i)`, `get_additional_data(name)`/`set_additional_data`. `get_handle_binary_image`/`set_handle_binary_image` are deprecated.

**PackedScene** (`classes/class_packedscene.rst`): `instantiate(edit_state: GenEditState = 0) -> Node`; `can_instantiate()`; `pack(node) -> Error` (packs only nodes whose `owner` is that node); `get_state() -> SceneState`. Every instance of a loaded scene shares its sub-resources (meshes, materials, `AnimationLibrary`, `Animation`s): `duplicate()` before changing one per instance, as `RigModel.load_clips` does with the library (`src/player/rig_model.gd:110`).

**ResourceUID** (`classes/class_resourceuid.rst`): static `uid_to_path(uid)`, `path_to_uid(path)`, `ensure_path(path_or_uid)`; instance `text_to_id`, `id_to_text`, `has_id`, `get_id_path`, `create_id`, `create_id_for_path`.

## Where the code already does this

- `scripts/common.sh` `import_assets`: runs `prepare_export.gd` and `write_import_settings.gd` with `--headless --script`, then `--headless --import`, logging to `.godot/import.log`. `scripts/run_tests.sh`: `--import` before tests, with or without `assets/`.
- `scripts/write_import_settings.gd`: writes `[remap]`/`[deps]`/`[params]` for every PNG, JPEG, EXR and HDR under `res://assets` (skipping `.gdignore` folders): `compress/mode` 2, `compress/normal_map` 1 or 2 from the glTF materials, `mipmaps/generate` true, `roughness/mode` 1, `detect_3d/compress_to` 0. It keeps existing uids and only rewrites files that change. It also sets `import_script/path` on every glTF under `assets/weapons/weapons/models` to `scripts/weapon_model_import.gd`, an `EditorScenePostImport` that removes a gun's second body (`...body_legacy`, never drawn) so its material and textures are not saved with the scene. That is an asset step, not game logic: weapon models only ever load as imported scenes, and `RigModel.is_spare_body`, the rule the script calls, still hides the body at runtime for an import made without it (another checkout sharing `assets/` whose branch lacks the script should report "Couldn't load post-import script" and import the model whole: inferred, not tried).
- `ConfigFile` drops a key whose value is `null` when it loads and saves an `.import` file (`nodes/root_script=null` disappears); the importer's default is the same `null`, so nothing changes.
- `scripts/weapon_tables.gd:137,144,254` and `scripts/surface_tables.gd:81`: write `importer="keep"` `.csv.import` files. They are committed for `reference/**/*.csv`.
- `src/map/map_importer.gd:403-421`: `load()` of the imported scene when `ResourceLoader.exists`, else `GLTFDocument.append_from_file` plus `generate_scene`. `tests/run_map_tests.gd:124` uses the runtime path.
- `src/map/export_offset_fix.gd:144-149`: touches the `.gltf` so Godot reimports after the `.bin` changes. `src/map/export_paint_channel.gd` renames `_TEXCOORD_4` to `COLOR_0` because the importer only reads attribute names it knows.
- `src/player/rig_model.gd:110-113`: duplicates the imported `AnimationLibrary` before renaming, because instances share it.
- Looks at odds, not verified: `scripts/write_import_settings.gd:98-104` does not set `compress/high_quality`, which the docs say is needed for BC6H (HDR) and BC7. asset-pipeline.md reports BC6H for the lightmap anyway. Check the imported lightmap's format (`Image.get_format()` on the texture's image) once.
- Looks at odds, not verified: all `.gltf` imports use the default `nodes/use_name_suffixes` = true. Valve node or clip names ending in a suffix token (`_col`, `_rigid`, `_noimp`), or clip names starting or ending in `loop`/`cycle`, would be changed by the editor import but not by the `GLTFDocument` fallback.
